# Урок 4. Подключение по OpenTelemetry OTLP

**Коротко.** Приложение с OpenTelemetry SDK отправляет данные прямо в New Relic. Нужны три вещи: адрес вашего региона по `https`, заголовок `api-key` со значением ключа лицензии и правильный протокол (gRPC на порт 4317 или HTTP на порт 4318).

## Термины этого урока

**OpenTelemetry (OTel).** Открытый стандарт и набор библиотек для трейсов, метрик и логов. Он не зависит от поставщика: те же данные можно отправить в New Relic, Aspire Dashboard, Grafana и т. д.

**OTLP.** OpenTelemetry Protocol — протокол передачи этих данных. Есть два варианта: OTLP/gRPC и OTLP/HTTP (protobuf).

**Endpoint.** Адрес, куда программа отправляет данные.

## Схема

```
GitHubBackup (OTel SDK, экспортер OTLP)
   │  TLS 1.2+, заголовок api-key: <ключ лицензии>
   ▼
https://otlp.nr-data.net:4317  (US)  или  https://otlp.eu01.nr-data.net:4317  (EU)
   │
   ▼
New Relic: Span, Metric, Log  ──>  сущность-сервис "GitHubBackup"
```

## Адреса по регионам

| Регион | Адрес | Порты |
|---|---|---|
| US | `https://otlp.nr-data.net` | 443, 4317, 4318 |
| EU | `https://otlp.eu01.nr-data.net` | 443, 4317, 4318 |
| JP | `https://otlp.jp.nr-data.net` | 443, 4317, 4318 |
| US FedRAMP | `https://gov-otlp.nr-data.net` | 443, 4317, 4318 |

- Порт **4317** — стандартный порт OTLP/gRPC.
- Порт **4318** — стандартный порт OTLP/HTTP.
- Порт **443** принимает оба протокола.
- Схема всегда `https`. New Relic требует TLS 1.2 или новее.

New Relic советует OTLP/HTTP для передачи через интернет. GitHubBackup использует gRPC. Это тоже поддерживается.

**Важно для OTLP/HTTP.** Если вы задаёте адрес для одного сигнала (только трейсы и т. п.), путь нужно писать полностью, например `.../v1/traces`. Иначе будет ошибка 404. Для gRPC путь не нужен.

## Заголовок api-key

New Relic узнаёт аккаунт по заголовку `api-key`. Его значение — ключ лицензии (урок 3).

Обычное приложение с OTel SDK задаёт заголовок стандартной переменной:

```
OTEL_EXPORTER_OTLP_HEADERS=api-key=<ключ лицензии>
```

GitHubBackup эту переменную не читает. У него свой ключ конфигурации (урок 5).

## Лимиты

| Лимит | Значение | Что происходит |
|---|---|---|
| Размер одного запроса (payload) | 1 MB (10^6 байт) | Запрос отклоняется с ошибкой |
| Длина строкового значения атрибута | 4095 символов | Значение обрезается |
| Длина имени атрибута | 255 символов | Имя обрезается |
| Атрибутов у ресурса | 64 | Лишние отбрасываются |
| Атрибутов у спана, точки метрики, лога | 128 | Лишние отбрасываются |
| Длина массива | 64 элемента | Лишние отбрасываются |
| Частота запросов | rate limit | Ошибка HTTP 429 / gRPC `ResourceExhausted` |

Когда New Relic меняет атрибут из-за лимита, он записывает событие `NrIntegrationError` (урок 11).

Сжатие: поддерживаются `gzip` и `zstd`. Сжатие уменьшает трафик, но лимит 1 MB считается для запроса.

## Temporality: delta и cumulative

**Temporality** — способ, которым метрика сообщает значение счётчика.

Пример. Программа сделала копию 3 репозиториев в первую минуту и 2 — во вторую.

```
                минута 1   минута 2   минута 3
cumulative:        3          5          5      итог с момента старта
delta:             3          2          0      прирост за интервал
```

- **Cumulative (накопительная).** Каждая отправка содержит сумму с момента старта программы. Это значение по умолчанию в .NET OTel SDK.
- **Delta (разностная).** Каждая отправка содержит только прирост за последний интервал.

**Что предпочитает New Relic.** New Relic рекомендует delta для счётчиков и гистограмм. Cumulative он тоже принимает: сам пересчитывает данные в delta. Но cumulative требует больше памяти в SDK и может дать больше принятых данных.

**Что это значит для GitHubBackup.** GitHubBackup отправляет cumulative (значение SDK по умолчанию). Данные дойдут и будут верными. Объём у GitHubBackup маленький, поэтому разница в расходе почти незаметна.
