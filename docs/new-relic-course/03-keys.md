# Урок 3. Ключи

**Коротко.** Для отправки данных по OTLP нужен ключ лицензии — тип **Ingest - License**. Ключ пользователя (User) и ключ браузера (Ingest - Browser) для OTLP не подходят. Храните ключ в переменной окружения, никогда в репозитории и в командной строке.

## Типы ключей

| Тип в интерфейсе | Для чего | Подходит для OTLP |
|---|---|---|
| **Ingest - License** (ключ лицензии) | Приём почти всех данных: APM, OpenTelemetry, логи, инфраструктура | **Да** |
| **Ingest - Browser** | Приём данных браузерного мониторинга | Нет |
| **User** (ключ пользователя, «personal API key») | Запросы и настройка через NerdGraph и REST API. Привязан к одному пользователю | Нет |
| Mobile app token | Мобильный мониторинг | Нет |

Ключ лицензии — строка из 40 символов. У каждого аккаунта есть исходный (original) ключ лицензии. Его нельзя удалить из интерфейса.

**Правило:** ключ лицензии только отправляет данные. Ключ пользователя читает и меняет настройки. Утечка ключа пользователя опаснее.

## Где создать ключ

Лучше создать отдельный ключ для GitHubBackup, а не брать исходный. Отдельный ключ легко отключить или заменить.

1. Откройте страницу ключей: меню пользователя (аватар или иконка профиля справа вверху) → **API keys**. Прямая ссылка: https://one.newrelic.com/api-keys (для EU — https://one.eu.newrelic.com/api-keys). В старых версиях интерфейса меню пользователя было внизу левой панели.
2. Нажмите **Create a key** справа вверху.
3. В поле **Key type** выберите **Ingest - License**.
4. Введите имя, например `githubbackup-otlp`. Описание необязательно.
5. Нажмите **Save**.
6. **Сразу скопируйте ключ.** Полное значение показывается только при создании. Потом интерфейс показывает только первые 8 символов. Иконка копирования в колонке **Value** копирует тоже только эту маску со звёздочками, а не полный ключ. Это касается и исходных ключей, которые New Relic создаёт вместе с аккаунтом.

Если ключ нужен снова, проще создать новый, а старый удалить.

Полный ключ можно получить и позже, но только через NerdGraph (API New Relic): в меню `...` у ключа скопируйте ID ключа и выполните запрос `actor { apiAccess { key(id: "<ID ключа>", keyType: INGEST) { key } } }`. Для этого курса такой путь не нужен.

## Как хранить ключ

```
Хорошо:   менеджер паролей ──> переменная окружения пользователя ──> программа
Плохо:    appsettings.json, репозиторий, командная строка, скриншот, чат
```

**Переменная окружения.** Программа читает ключ при старте. Значение не попадает в файлы проекта. В Windows задайте переменную для своего пользователя (не для системы).

**Почему не командная строка.** Аргументы процесса видят другие программы на компьютере (например, Диспетчер задач и `Get-CimInstance Win32_Process`). Они также попадают в историю оболочки.

**Почему не репозиторий.** Репозиторий может стать публичным. Ключ останется в истории git, даже если файл потом исправить. Боты ищут ключи в публичных репозиториях за минуты.

**Если ключ утёк.** Создайте новый ключ, поменяйте переменную, затем удалите или деактивируйте старый ключ на странице **API keys** (меню `...` у ключа). Деактивация сразу останавливает приём данных по этому ключу.
