# Урок 1. Что такое New Relic и основные термины

**Коротко.** New Relic — облачная платформа наблюдаемости (observability). Ваше приложение отправляет в неё трейсы, метрики и логи. New Relic хранит эти данные, показывает их в интерфейсе, строит графики и шлёт уведомления о проблемах.

## Как данные попадают в New Relic

```
Приложение ──(OTLP + ключ)──> приёмник New Relic ──> хранилище (NRDB)
                                                         │
                       дашборды, алерты, NRQL-запросы <──┘
```

Приложение не хранит ничего у себя. Оно только отправляет данные. Всё остальное делает New Relic.

## Термины

Каждый термин объяснён один раз. Дальше курс использует именно эти слова.

**Организация (organization).** Верхний уровень. Организация владеет аккаунтами, пользователями и подпиской. Регион данных задаётся для организации.

**Аккаунт (account).** Контейнер для данных. У аккаунта есть номер (account ID) и свой ключ лицензии. Бесплатная регистрация создаёт одну организацию с одним аккаунтом.

**Сущность (entity).** Любой объект, о котором New Relic собирает данные: сервис, хост, база данных, браузерное приложение. У каждой сущности есть уникальный GUID. New Relic создаёт сущность сам, когда видит новые данные.

**APM-сервис (APM service).** Сущность типа «сервис приложения». APM — Application Performance Monitoring, мониторинг производительности приложений. Для данных OpenTelemetry сервис создаётся по атрибуту ресурса `service.name`. У GitHubBackup это `GitHubBackup`.

**Трейс (trace).** Путь одной операции через программу от начала до конца. Пример: один запуск резервного копирования.

**Спан (span).** Один шаг внутри трейса. У спана есть имя, начало, длительность, статус и атрибуты. Спаны вложены друг в друга, как дерево. В New Relic спаны хранятся как тип данных `Span`.

```
трейс = дерево спанов
backup.run                 корневой спан
├── backup.discovery       дочерний спан
└── backup.repository      дочерний спан
    └── fetch              внук
```

**Метрика (metric).** Число, которое программа измеряет со временем: счётчик, длительность, размер. В New Relic метрики хранятся как тип `Metric`.

**Лог (log).** Текстовая запись о событии: время, уровень, сообщение, атрибуты. В New Relic логи хранятся как тип `Log`.

**Атрибут (attribute).** Пара «имя = значение» на спане, метрике, логе или ресурсе. Пример: `githubbackup.status = Failed`.

**NRQL.** New Relic Query Language — язык запросов, похожий на SQL. Каждый график в New Relic — это NRQL-запрос. Пример: `FROM Span SELECT count(*) SINCE 1 day ago`.

**Дашборд (dashboard).** Страница с набором графиков. Каждый график строится NRQL-запросом.

**Алерт (alert).** Правило, которое проверяет данные и сообщает о проблеме. Алерт состоит из трёх частей:

```
Alert policy (политика) ──> Alert condition (условие, NRQL + порог) ──> Issue (проблема) ──> Destination (email, Slack...)
```
