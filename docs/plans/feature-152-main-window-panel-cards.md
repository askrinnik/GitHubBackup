## 1. Цель

Главное окно (FR-12.1) показывает четыре отдельные панели-карточки одного стиля, сверху вниз:

```
дерево            (карточка 1)
== разделитель ==
живая лента лога  (карточка 2, FR-12.3)
== разделитель ==
результаты        (карточка 3: заголовок запуска, ошибки, предупреждения, таблица, FR-12.4)
итоги             (карточка 4: обнаруженные репозитории, отмена, счётчики, путь к логу, FR-12.4)
```

Узлы дерева получают значки по виду (аккаунт, группа отдельных репозиториев, репозиторий) из шрифта
`Segoe Fluent Icons, Segoe MDL2 Assets`, как значки разделов FR-12.5. Колонки дерева остаются выровненными.
Разделители и сохранённые высоты (FR-12.10) работают и со старым `ui-settings.json`. Обе темы FR-12.9.

## 5. Подход

1. PRD.
2. `CardPanel` и общие стили в `App.xaml`; инлайн-стиль `SummaryCard` удаляется.
3. Раскладка: результаты — `RunSummaryHeader`, `RunSummaryErrors`, `RunSummaryWarnings`, `RunSummaryNoRepositories`,
   линия-разделитель, `RunSummaryTable`; итоги — `RunSummaryDiscovery` (свой `MaxHeight` и прокрутка),
   `RunSummaryCancelled`, `RunSummaryTotals`, `RunSummaryLogPath`. Внешняя прокрутка панели результатов
   (`RunResultsScroll`) сохраняет правило «таблица не меньше заголовка и одной строки, иначе прокручивается вся
   карточка».
4. Значки: аккаунт и группа — `StackPanel` [значок, имя]; репозиторий — первая колонка фиксированной ширины со
   значком, общие колонки не сдвигаются.
5. Рамка верхних узлов: варианты A (без рамок) и B (рамка у каждого аккаунта и группы) сравниваются на
   скриншотах; в коде остаётся выбранный (см. «Решения»).
6. Code-behind разделителя для новых имён элементов.

## 9. Решения

Пакет идёт без ревью плана; решения приняты основной сессией.

- **Карточка — `CardPanel : Border`, а не `GroupBox` со своим шаблоном.** FR-12.9 разрешает собственным стилям менять
  у элемента Fluent только размеры и отступы; замена шаблона `GroupBox` выходит за это. `Border` не имеет стиля
  Fluent, а наследник добавляет только automation peer. Альтернатива — `GroupBox` с заменённым шаблоном.
- **Правило `.claude/rules/wpf-mvvm.md` не меняется.** Внутри панели результатов линия отделяет строки заголовка
  от таблицы, как требует правило; между таблицей и итогами линию заменяет граница двух карточек. Альтернатива —
  переписать пункт «Separate regions visibly».
- **Разделители между карточками** — прозрачный захват, он же зазор, курсор `SizeNS`, без линии. Альтернатива —
  линия 1 px по центру зазора.
- **Цвет значков** наследует цвет текста узла (тема и выделение). Альтернатива — `TextFillColorSecondaryBrush`.
- **`NoRepositoriesLine`** в панели результатов (пустое состояние таблицы), **`CancelledLine`** в панели итогов.
- **Глифы:** аккаунт `Contact` (U+E77B), группа отдельных репозиториев `Library` (U+E8F1), репозиторий `Folder`
  (U+E8B7). Сравнивались `Folder` и `Code` (U+E943) на скриншотах в темах Light и Dark: фигурные скобки `Code`
  читаются как символы текста рядом с именем, `Folder` читается как значок и не спорит с именем. Каждый глиф —
  один строковый ресурс в `App.xaml`.
- **Рамка верхних узлов дерева: нет (вариант A).** Вариант B (своя рамка у каждого аккаунта и группы) сравнивался
  на скриншотах в обеих темах: внутри карточки дерева получаются вложенные рамки, они повторяют рамку панели,
  отнимают ширину и в тёмной теме выглядят тяжело. Стиль варианта B не оставлен в коде: дерево использует
  `TreeItemStyle` для всех уровней.
- **Скриншоты** сняты офскрин-рендером окна (`RenderTargetBitmap`) во временной установке: рабочая станция была
  заблокирована, и снимки живого окна через netwright получались пустыми.
