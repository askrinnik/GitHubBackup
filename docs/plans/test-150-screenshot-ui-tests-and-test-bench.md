## 1. Цель

Два инструмента для визуальной проверки (PRD §6.12: FR-12.1, FR-12.2, FR-12.4, FR-12.9; §11, слой «UI end-to-end»).
Поведение приложения не меняется.

1. **Скриншотные UI-тесты** в `GitHubBackup.App.UITests`: снимок ключевого окна в заданном состоянии и проверки по
   измерениям одного снимка — выравнивание строк таблиц, текст не касается рамок, рамки и разделители видны.
2. **Тестовый стенд** `scripts/test-bench.ps1`: одна команда поднимает копию приложения с заглушкой GitHub API по
   сценарию; реальная установка и реальный токен не участвуют.

Эталонных картинок нет; `.claude/rules/tests.md` и PRD §11 не меняются.

## 4. Затронутые проекты и типы

**GitHubBackup.TestUtilities** (общие для UI-тестов и стенда):

- `AppSettingsJson`: `Valid(apiBaseUrl)` и константа `Token` (перенос из `AppInstallation`).
- `UiSettingsJson`: текст `ui-settings.json` (тема, `LogPanelHeight`, `SummaryPanelHeight`).
- `UiScenario`, `UiScenarios`: именованные сценарии поверх `GitHubApiStub` и `BackupConfigJson` —
  `missing-repository`, `renamed-repository`, `new-repositories`, `discovery-review`, `many-rows`.
- `IsolatedAppProcess`: `ProcessStartInfo` без унаследованных `GitHubBackup__*` и `GIT_*`, с
  `DOTNET_ENVIRONMENT=Production` (перенос из `AppSession`).

**GitHubBackup.App.UITests:**

- `AppInstallation`, `AppSession`: переход на общие помощники, поведение тестов не меняется.
- `PixelImage`, `ScreenCapture` (снимок `Capture.Element` с проверкой пустого снимка), `LayoutMeasurement` (фон,
  маска текста без линий рамок, верх текста, полосы строк, контраст края), `TableGeometry` (колонки и строки таблицы
  из UIA, для `DataGrid` и `ListView`).
- `LayoutMeasurementTests` (синтетические картинки), `MainWindowScreenshotTests`, `DiscoveryDialogScreenshotTests`.

**GitHubBackup.TestBench** (новый консольный проект `net10.0-windows`, вспомогательный, как `TestUtilities`):
хостит `GitHubApiStub` со сценарием `UiScenarios`, готовит временную установку, печатает пути, по умолчанию
запускает приложение, ждёт Enter, Ctrl+C или выхода приложения, убирает за собой. Аргументы — `System.CommandLine`.

**Корень и документация:** `scripts/test-bench.ps1`, `src/GitHubBackup.slnx`, `docs/development.md`, `CLAUDE.md`,
`.claude/rules/wpf-mvvm.md`, `.claude/rules/msbuild.md`, `docs/ai/README.md`.

## 5. Подход

1. Общие помощники в `TestUtilities`, перевод `AppInstallation` и `AppSession`.
2. Помощники измерения и их тесты на синтетике.
3. `MainWindowScreenshotTests` (Light и Dark): одна строка (`missing-repository`), много строк со строками
   обнаружения (`many-rows`), минимальная высота (`SummaryPanelHeight: 80`), рамки и разделитель.
4. `DiscoveryDialogScreenshotTests` (Light и Dark): сценарий `discovery-review`, четыре вида строк, выделенная
   строка.
5. Проект стенда и скрипт.
6. Документация.
7. Проверка откатом.

Допуски — в физических пикселях с учётом масштаба. Пороги контраста калибруются на текущей вёрстке в обеих темах:
порог — половина наименьшего измеренного значения; константа с комментарием «почему».

## 6. Тесты

- `LayoutMeasurementTests`: верх текста на одной строке и со смещённой ячейкой; рамки элементов управления не
  считаются текстом; строка, обрезанная краем; полная линия-разделитель не текст; видимая и бледная рамка; пустой
  снимок даёт ошибку.
- `MainWindowScreenshotTests` (`[Theory]` по теме): одна строка; много строк со строками обнаружения; минимальная
  высота; рамки и разделитель.
- `DiscoveryDialogScreenshotTests` (`[Theory]` по теме): четыре вида строк на одной линии; выделенная строка;
  текст не касается краёв таблицы.
- Существующие UI-тесты проходят после рефакторинга.

## 9. Решения

Пакет идёт без ревью плана; решения приняты основной сессией.

- **D0. Только измерения, без эталонных картинок** (решение пользователя): `.claude/rules/tests.md` и PRD §11 не
  меняются.
- **D1. Стенд — консольный проект `GitHubBackup.TestBench`**, скрипт — тонкая обёртка. Альтернативы: WireMock
  StandAlone с JSON-маппингами (повторяет ответы заглушки), `Add-Type` на `TestUtilities.dll` (хрупкие
  зависимости), «тест»-точка входа в UITests (смешивает тесты и инструмент).
- **D2. Пустой снимок роняет тест с понятным сообщением.** Альтернатива — динамический пропуск: пропущенный набор
  выглядит зелёным.
- **D3. Снимок через `Capture.Element`.** Альтернатива `PrintWindow` при блокировке экрана тоже бесполезна.
- **D4. Помощники измерения — в `GitHubBackup.App.UITests`**, их единственном потребителе. Альтернатива —
  `TestUtilities` (там нет тестов, понадобился бы `System.Drawing.Common`).
- **D5. `msbuild.md`:** оговорка, что тестовые пакеты подключают и вспомогательные проекты `TestUtilities` и
  `TestBench`. Альтернатива — не трогать правило, оставив его расходящимся с кодом.
- **D6. Выравнивание проверяется по всем видимым колонкам**, включая шаблонные (правило «One baseline per table
  row»). Если калибровка покажет расхождение текста внутри элементов Fluent больше допуска, проверка
  ограничивается текстовыми колонками, а расхождение попадает в итоговый отчёт.
- **D7. Стенд по умолчанию запускает приложение**; `-NoLaunch` только готовит папку и печатает путь (для netwright).
- **D8. `wpf-mvvm.md`, «Verifying the running app»:** ссылка на стенд вместо ручной временной установки; netwright
  запускает exe стенда по пути, а не `project=`, потому что папка сборки может содержать настройки разработчика.
- **D9. Калибровка при заблокированном экране.** Во время пакета рабочая станция заблокирована: WPF не рисует окна,
  живой снимок пустой, ввод мыши FlaUI отклоняется. Пороги и проверка откатом проверяются на внеэкранных рендерах
  окна (временный вспомогательный инструмент вне репозитория); живой прогон скриншотных тестов — на
  незаблокированном рабочем столе.

- **D10. Отклонения при реализации.** Общие пороги и проверки обоих классов скриншотных тестов вынесены в
  `ScreenshotAssert`; `UiSettingsJson` задаёт размер окна (1000×720), чтобы снимки были одного размера; ячейка,
  у которой текста больше чем в 1,6 раза против медианы строки (двухстрочная папка у строки Renamed), не входит в
  проверку выравнивания. Калибровка на внеэкранных рендерах при масштабе 1,0: контраст рамок 57–137 (порог 28),
  разделителя 74–137 (порог 37), текста выделенной строки 82–119 (порог 41), разброс верха текста в строке 0–1 px
  (допуск `ceil(2 * scale)`). Откат: (а) разброс 6–9 px, проверка падает; (б) строка таблицы сжимается до 4 px,
  проверка падает; после возврата обе проходят.
