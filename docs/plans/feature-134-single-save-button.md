## 1. Цель

FR-12.5 (PRD 0.37, пункт «**Сохранение.**»). В редакторе настроек остаётся одна кнопка `Save`. Она сохраняет все изменённые группы: конфигурацию (`backup-config.json`), пути к инструментам и телеметрию (`user-settings.json`, §7.2) и введённый токен (Credential Manager).

Save работает в две фазы:
1. Проверяет все изменённые группы. Если есть хотя бы одна ошибка, ничего не пишется.
2. Пишет только изменённые группы.

Если запись не удалась, редактор остаётся открытым. После успеха редактор возвращается к дереву и не задаёт вопроса о несохранённых изменениях. Cancel спрашивает подтверждение, только если есть несохранённые изменения. Тема сохраняется сразу при выборе (FR-12.9).

## 2. Критерии приёмки

Из issue:
1. PRD обновлён (0.37, FR-12.5 и строка истории). Issue называет версию 0.36, но её занял #135.
2. Одна кнопка сохранения `Save`; кнопок `Save tool paths`, `Save telemetry settings`, `Save token` нет.
3. `Save` пишет изменённые конфигурацию, пути к инструментам, телеметрию и введённый токен; неизменённые группы не пишутся.
4. Ошибка проверки в любой группе останавливает Save до любой записи: хранилища не меняются, ошибки видны у полей.
5. Ошибка записи одной группы показывается в диалоге. Редактор остаётся открытым, несохранённые изменения остаются в полях. Уже записанные группы остаются записанными, Save можно повторить.
6. После успешного Save редактор возвращается к дереву без диалога о несохранённых изменениях.
7. Cancel без изменений возвращается к дереву без вопроса; с изменениями — после подтверждения.
8. `Check token` остаётся и ничего не сохраняет; тема по-прежнему сохраняется сразу при выборе (FR-12.9).
9. Первый запуск (нет `backup-config.json`): конфигурация считается изменённой, Save создаёт файл.
10. Видимые пункты проверены в запущенном приложении (netwright).
11. Покрыто тестами, CI зелёный.

Добавлено по проверке покрытия:
- (добавлено) Повторный Save после частичной ошибки записи не пишет заново группы, которые уже записаны.
- (добавлено) Токен только из пробелов — ошибка проверки `The token cannot be empty.` у поля токена. Пустое поле означает «токен не меняется».
- (добавлено) Первый запуск: Cancel без правок не спрашивает. «Считается изменённой» действует только для Save.
- (добавлено) Если `backup-config.json` не читается, Save доступен и пишет только изменённые инструменты, телеметрию и токен.
- (добавлено) Ошибки путей к инструментам и телеметрии без своего поля попадают в `GeneralErrors`.

## 4. Подход

1. **Изменённая группа:**

   | Группа | Признак |
   |---|---|
   | Конфигурация | `IsLoaded && (IsDirty \|\| IsNewConfig)` |
   | Инструменты | `_toolsDirty` |
   | Телеметрия | `_telemetryDirty` |
   | Токен | `!string.IsNullOrEmpty(Token)` |

   `HasUnsavedChanges` не меняется.

2. **Проверка** всех изменённых групп без короткого замыкания: конфигурация (`_configStore.Validate`), инструменты (`ValidateTools()`), телеметрия (`ValidateTelemetry()`), токен (только пробелы → `TokenError`). Ошибки без поля → `GeneralErrors`. Есть ошибка → выход без записи.

3. **Запись** в порядке конфигурация → инструменты → телеметрия → токен. Успешная запись сразу снимает признак изменения своей группы. На первой ошибке запись останавливается, `_dialogs.ShowError(SaveFailedTitle, masked)`; `TokenStoreException` в лог не пишется (S2). `BackupConfigException` остаётся в `GeneralErrors`. Редактор не закрывается.

4. **Успех** → `NavigateTo<RepositoriesViewModel>()` без `ConfirmLeave()`.

5. **Перекрытый токен.** После записи токена `_tokenProvider.GetTokenAsync` проверяет, какой источник победил. Если другой — `ShowInformation` с именем источника (без значения) перед возвратом к дереву.

6. **CanSave** = `IsLoaded || HasLoadError`; `[NotifyCanExecuteChangedFor(nameof(SaveCommand))]` на `_loadError`.

## 5. Тесты

ViewModel-тесты: успех по каждой группе и для всех (`Received.InOrder`), ничего не изменено, пустой токен, перекрытый и неперекрытый токен; theory ошибок проверки по группам; обе ошибки сразу; неизменённая группа не проверяется; ошибки записи по каждому хранилищу (диалог, нет навигации, поля сохранены, токен не в логе); повтор после ошибки пишет только оставшееся; первый запуск; нечитаемая конфигурация; Save недоступен до загрузки; `Cancel_UnsavedTelemetry_Asks`.

UI-тесты: `Save_AbsoluteGitPath_WritesUserSettingsAndReturnsToTree`, `Save_TelemetryEnabledWithEndpoint_WritesOpenTelemetrySection`, `Open_ShowsOneSaveButtonWithoutGroupSaveButtons`, `Open_ShowsTelemetryGroupWithItsFields`. Save с токеном в UI-тестах не проверяется: он пишет в настоящий Credential Manager.

## 6. Вне объёма

- Одна атомарная запись `user-settings.json` для инструментов и телеметрии.
- Откат уже записанных групп: PRD оставляет их записанными.
- Индикатор занятости и отмена во время Save.

## 7. Decisions

Решения приняты в пакете `implement-issues` без отдельного обзора плана:
1. При нечитаемом `backup-config.json` Save доступен и пишет только инструменты, телеметрию и токен. Альтернатива — Save недоступен; тогда эти группы при ошибке загрузки сохранить нельзя.
2. Предупреждение о токене из источника с более высоким приоритетом показывается информационным диалогом перед возвратом к дереву. Альтернатива — убрать предупреждение.
3. Запись идёт в порядке конфигурация → инструменты → телеметрия → токен и останавливается на первой ошибке. Альтернатива — писать остальные группы и показать все ошибки.
4. Ошибка записи токена показывается диалогом `Settings not saved`, а не строкой у поля, как требует критерий 5.
