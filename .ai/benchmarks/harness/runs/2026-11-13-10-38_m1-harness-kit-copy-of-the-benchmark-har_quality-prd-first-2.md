**Кратко.** Это изменение в три слоя: parser в `Cli`, фильтр в `Core` и новое поле `PushedAt` из GitHub API. Сначала нужна правка PRD. По `CLAUDE.md` и `.claude/rules/cli.md` новая опция CLI начинается с изменения PRD, а код пишется после вашего одобрения.

## Что я нашёл

- Опции `backup` объявлены в `CliCommandLine.Parse`. Они попадают в `BackupCommandOptions(Filter, DryRun, Silent)`.
- `BackupCommandHandler` передаёт `Filter` в `BackupRunRequest`. Оркестратор применяет его в `SelectIncluded` через `BackupRunFilter.Includes(BackupWorkItem)`.
- `GitHubRepository` сейчас не содержит даты push. В нём есть `Id`, `Owner`, `Name`, флаги, `DefaultBranch` и `HtmlUrl`. Эту дату надо добавить.
- Данные из GitHub есть не у всех репозиториев. `GitHubRepository` приходит только из обнаружения (discovery). При `--repo` обнаружение пропускается (`DiscoverAsync`). Репозитории, добавленные в конфиг вручную, тоже не проходят через список аккаунта. Для них дату надо запрашивать отдельно.

## План изменений

**1. PRD (первым, после вашего одобрения)**
- В `docs/PRD.md` в FR-9.2 добавить строку `--since <date>`. Поднять версию и добавить строку в историю изменений.
- Описать семантику: дата в формате `yyyy-MM-dd`, граница — начало этих суток в UTC, условие `pushed_at >= since`.
- Добавить правило для репозитория без известной даты и правило совместной работы с `--repo`, `--account` и `--dry-run`.
- Затем обновить `README.md`, где описаны опции.

**2. Core**
- `GitHubRepository`: добавить `DateTimeOffset? PushedAt`. Поле может быть пустым, потому что у пустого репозитория `pushed_at` бывает `null`.
- `IGitHubApi`: если списки аккаунтов не покрывают все записи, добавить метод получения одного репозитория (или только его `PushedAt`).
- `BackupRunFilter`: добавить `Since` (`DateTimeOffset?`) и фабрику или `with`-вариант, который сочетается с `All`, `ForAccount` и `ForRepository`. Сейчас конструктор приватный, и фильтры взаимоисключающие. `Since` должен комбинироваться с ними.
- `BackupOrchestrator`: после `SelectIncluded` добавить шаг, который отбрасывает записи с `PushedAt < Since`. Каждый пропуск логируется через `BackupOrchestratorLog`, как у `RepositoryFilteredOut`.
- Пропущенный репозиторий не меняет состояние: ни clone, ни fetch, ни архив, ни запись в state. В итоге он должен быть виден как «пропущен», а не как «не изменился».

**3. Infrastructure**
- Octokit-адаптер `IGitHubApi` заполняет `PushedAt` из `pushed_at` в ответе API.

**4. Cli**
- `CliCommandLine.Parse`: `Option<string>("--since")` с `HelpName = "date"` и валидатором. Формат неверный — ошибка с понятным сообщением, а само значение в сообщение не включается, как в `ValidateValue`.
- `BackupCommandOptions`: добавить `DateTimeOffset? Since`. Обновить `Default` и `CreateBackupOptions`.
- `BackupCommandHandler`: положить `Since` в фильтр запроса.
- Время получать только из `TimeProvider`. Даты из `DateTime.Now` не брать.

**5. Тесты**
- `Cli.Tests`: разбор допустимой и недопустимой даты, комбинации с `--account`, `--repo`, `--dry-run`.
- `Core.Tests`: граница включительно, `PushedAt == null`, пропущенные репозитории не трогают state, фильтр по аккаунту вместе с `--since`.
- `BackupSummaryRenderer`: показать пропущенные по дате репозитории. Проверить вывод через `TestConsole`.

## Вопросы, которые надо решить в PRD

1. **Репозиторий без `PushedAt`** (пустой или нет данных от API). Обрабатывать или пропускать? Я бы обрабатывал: безопасная ошибка — лишний бэкап, а не пропуск.
2. **Часовой пояс.** Предлагаю UTC, потому что `pushed_at` приходит в UTC. Локальная дата давала бы неоднозначность у границы суток.
3. **Что видит `pushed_at`.** Я не проверял это по документации, но считаю, что `pushed_at` не отражает изменения в wiki. Такой репозиторий может быть пропущен при изменённой wiki. Это стоит записать в PRD как известное ограничение.
4. **`--repo` с `--since`.** Допускать ли их вместе? Для этого нужен лишний запрос в API, потому что обнаружение при `--repo` пропускается.
5. **Лишние запросы.** Для вручную добавленных записей это один запрос на репозиторий. Нужен ли для этого кэш или пакетный запрос (batch)?
