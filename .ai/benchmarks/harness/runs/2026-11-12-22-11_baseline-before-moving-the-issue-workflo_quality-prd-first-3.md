**Коротко.** Опцию `--since` нельзя сделать только в CLI. Данных о дате последнего push в коде сейчас нет: ни `GitHubRepository`, ни `BackupWorkItem` их не хранят (поиск по `PushedAt` и `pushed_at` в `src` ничего не нашёл). Значит, нужны три изменения: правка PRD, поле `PushedAt` из GitHub API и фильтр в ядре. Парсер в CLI тут самая простая часть. Я ничего не менял.

## Шаг 0. PRD (по правилам проекта идёт до кода)

Я предлагаю такие правки в `docs/PRD.md`:
- **FR-9.2:** новая строка `--since <yyyy-MM-dd>` — «Только репозитории с push не раньше этой даты (по `pushed_at` из GitHub)». Фраза «`--account` и `--repo` вместе не используются» не меняется: `--since` совместим с обоими.
- **Новое FR-9.x** с точной семантикой: формат даты, часовой пояс, обработка репозиториев без `pushed_at`, влияние на обнаружение (см. вопросы ниже).
- Версия 0.20 в шапке и строка в истории изменений. После этого обновляю `README.md`, затем issue с `## Зависимости`, затем план в `docs/plans/feature-<n>-since-option.md`.

## Что менять в коде

```
CLI (разбор)  →  BackupRunFilter (Core)  →  BackupOrchestrator  →  IGitHubApi (дата push)
```

1. **`GitHubBackup.Core/GitHub/GitHubRepository.cs`**
   - Добавить `DateTimeOffset? PushedAt = null` последним параметром с default.
   - Три теста, которые создают запись позиционно, продолжат компилироваться.

2. **`GitHubBackup.Infrastructure` (Octokit)**
   - В маппинге `Repository` → `GitHubRepository` заполнять `PushedAt` из `Repository.PushedAt`.
   - Я не проверял, где находится маппинг и есть ли в `IGitHubApi` метод получения одного репозитория. Это нужно проверить при реализации.
   - Обнаружение уже получает список репозиториев аккаунта, поэтому для них дата приходит бесплатно.
   - Для отдельных репозиториев из конфига и для `--repo` (там обнаружения нет, FR-2.7) нужен один запрос API на репозиторий. Возможно, потребуется новый метод `IGitHubApi`.

3. **`GitHubBackup.Core/Runs/BackupRunFilter.cs`**
   - Добавить `DateTimeOffset? PushedSince` и метод `WithPushedSince(DateTimeOffset)`. Конструктор у типа приватный.
   - Этот фильтр уже есть в `BackupRunRequest`, поэтому менять сигнатуры хендлера и оркестратора не придётся.
   - `Includes(BackupWorkItem)` остаётся проверкой по именам. Проверка по дате делается отдельно, потому что `BackupWorkItem` даты не знает.

4. **`GitHubBackup.Core/Runs/BackupOrchestrator.cs`**
   - После `SelectIncluded` добавить шаг «оставить репозитории с `PushedAt >= PushedSince`».
   - Каждый отброшенный репозиторий пишется в лог через `LoggerMessage`, как сделано для `RepositoryFilteredOut`.
   - Дата берётся из результата обнаружения. Если её там нет, делается запрос API.

5. **`GitHubBackup.Cli/CliCommandLine.cs`**
   - Добавить `Option<string>("--since")` с `HelpName = "date"` и добавить её в `backup.Options`.
   - Валидатор: `DateOnly.TryParseExact("yyyy-MM-dd", InvariantCulture)`. Сообщение об ошибке не содержит введённое значение, как в существующем `ValidateValue`.
   - `CreateBackupOptions` накладывает дату на фильтр через `WithPushedSince`.
   - `BackupCommandOptions` менять не нужно.

6. **Документация кода.** Нужны `///`-комментарии на всех новых членах, без ссылок на issue и без «теперь»/«раньше».

## Вопросы, на которые нужен ваш ответ до PRD

1. **Часовой пояс.** Считать дату началом суток в UTC (я рекомендую) или в локальном времени? `pushed_at` в API приходит в UTC.
2. **Репозиторий без `pushed_at`** (пустой) **или ошибка запроса даты.** Я рекомендую включать такой репозиторий в запуск и писать предупреждение: для бэкапа безопаснее не пропустить лишнее, чем потерять нужное. Альтернатива — исключать.
3. **Обнаружение.** Я рекомендую оставить его без изменений: новые и пропавшие репозитории по-прежнему обрабатываются по FR-2.7. `--since` ограничивает только список бэкапа. Если нужно иначе, это надо записать в PRD.
4. **История запусков.** PRD (около строки 286) говорит, что в истории хранится фильтр. Если сохранять там и `--since`, потребуется миграция EF через `dotnet ef`. Я рекомендую сохранять, чтобы запуск было понятно разбирать позже. Это можно вынести в отдельный issue.
5. **Отброшенные репозитории в сводке.** Я рекомендую вести себя как при `--account`: только запись в лог, без строки в таблице. Если нужны строки `Skipped`, придётся менять FR-9.7.

## Ограничение, которое стоит записать в PRD

`pushed_at` не меняется при push в wiki. Репозиторий с новой правкой только в wiki при `--since` будет пропущен. Для регулярных запусков по расписанию лучше полагаться на обычную быструю проверку `ls-remote`, а `--since` использовать как ручное ограничение.
