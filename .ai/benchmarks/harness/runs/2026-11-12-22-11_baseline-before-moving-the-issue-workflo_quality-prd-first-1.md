## Что менять в коде

```
Cli: CliCommandLine → BackupCommandOptions → BackupCommandHandler
        ↓
Core: BackupRunFilter / BackupRunRequest → BackupOrchestrator.SelectIncluded
        ↓
Core: IGitHubApi → GitHubRepository (+PushedAt)
        ↓
Infrastructure: Octokit-адаптер (заполняет PushedAt)
```

1. **`CliCommandLine.cs`** (около строки 74). Добавить `Option<DateOnly?>("--since")` с описанием и `HelpName = "yyyy-MM-dd"`. Ошибку неверного формата вернуть валидатором парсера, как у `--repo`. Ошибку «`--since` вместе с `--repo`» (если вы так решите) добавить в `backup.Validators` рядом с проверкой `--account`/`--repo`. Затем передать значение в `BackupCommandOptions`.
2. **`BackupCommandOptions.cs`**. Добавить параметр `DateOnly? Since`. В `Default` он равен `null`.
3. **`BackupCommandHandler.cs`**. Передать `Since` в `BackupRunRequest`, как сейчас передаются `DryRun` и `Mode`.
4. **`BackupRunRequest.cs`**. Добавить `DateTimeOffset? PushedSince`. Границу дня надо переводить в UTC один раз, на входе. `TimeProvider` нужен, только если дата будет считаться относительно «сегодня».
5. **`GitHubRepository.cs`**. Добавить `DateTimeOffset? PushedAt`. Тип nullable, потому что у пустого репозитория `pushed_at` может быть `null`. Заполнять поле в Octokit-адаптере в Infrastructure (`pushed_at` приходит в ответах `/user/repos`, `/orgs/{org}/repos`, `/users/{login}/repos` и `/repos/{owner}/{name}`).

Для этого понадобятся поле в `RunEntity` и новая миграция через `dotnet ef migrations add` (руками миграции не правят). Это решение тоже стоит включить в PRD.

## Главная проблема: откуда брать дату пуша

`BackupWorkItem` строится из конфигурации, а в ней нет `pushed_at`. Обнаружение (FR-2.7) ищет только новые, пропавшие и переименованные репозитории. Я не читал `DiscoveryService`, поэтому не знаю, сохраняет ли он данные уже известных репозиториев. Варианты:

| Вариант | Плюс | Минус |
|---|---|---|
| **A.** Использовать списки репозиториев, которые обнаружение уже запрашивает, и сопоставлять по `Id` | Ни одного лишнего запроса | Нужно протянуть `PushedAt` через `DiscoveryResult` в оркестратор. Ломается с `--repo`, где обнаружения нет |
| **B.** Вызывать `GetRepositoryByIdAsync` для каждого репозитория конфигурации | Просто и локально | N запросов; для больших аккаунтов это расход лимита API |

Я бы выбрал **A**. Для репозиториев, которых нет в списке обнаружения (отдельные `config.Repositories`), использовать запасной вариант **B**.

## Оговорка

`pushed_at` показывает последний пуш в репозиторий. Он не равен проверке `ls-remote`, которую использует бэкап для обнаружения изменений. Пуш в wiki, насколько я знаю, `pushed_at` основного репозитория не меняет, так что `--since` может пропустить репозиторий, у которого изменилась только wiki. Это стоит прямо записать в PRD.
