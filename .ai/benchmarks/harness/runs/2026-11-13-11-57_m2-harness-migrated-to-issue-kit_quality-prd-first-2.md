## Что я нашёл

- В FR-9.2 перечислены параметры `backup`: `--account`, `--repo`, `--dry-run`, `--silent`, `--config`. Параметра `--since` там нет.
- Фильтр запуска — `BackupRunFilter` в `Core/Runs`. Оркестратор применяет его в `BackupOrchestrator.SelectIncluded`.
- Метод `BackupRunFilter.Includes` получает только `BackupWorkItem`, то есть запись из `backup-config.json`. Даты последнего push там нет.
- Запись `GitHubRepository` (`Core/GitHub`) тоже не хранит дату push. Строка `PushedAt` в коде `src` не встречается.
- `DiscoveryService.DiscoverAsync` уже получает список репозиториев из GitHub API, но не пропускает его дальше в выбор элементов.

## Нужно решить до PRD

1. **Что значит «pushed on or after»?** Предлагаю поле API `pushed_at`. Сравнивать его с датой нужно в UTC.
2. **Формат даты и граница.** Предлагаю `yyyy-MM-dd`, начало суток UTC включительно. Ошибка формата даёт код `2`, как другие ошибки командной строки (FR-9.10).
3. **Репозиторий, которого нет в списке обнаружения** (пропавший, вне области обнаружения). У него нет `pushed_at`. Предлагаю не пропускать его молча, а явно показать статус `Skipped` с причиной. Это тоже решение для PRD.
4. **Совместимость с другими параметрами.**
   - С `--account` комбинация естественна: фильтры складываются.
   - С `--repo` обнаружения нет, значит нет и `pushed_at`. Тогда параметры либо несовместимы, либо `--repo` отдельно запрашивает репозиторий через API. Предлагаю сделать их несовместимыми, по образцу правила для `--account` и `--repo`.
5. **Обнаружение с `--since`.** Оно должно видеть все репозитории, иначе новые и пропавшие будут определяться неверно. Дата ограничивает только обработку, а не обнаружение.
6. **Что писать в историю.** Предлагаю добавить дату в запись запуска рядом с `AccountFilter` и `RepositoryFilter` (`RunHistoryEntryBuilder`). Для этого нужна миграция EF, сгенерированная через `dotnet ef`. Если история не нужна, этот шаг можно убрать.
