## Главная проблема

Дата последнего push нигде не хранится. Grep по `src` не нашёл `PushedAt` или `pushed_at`. `BackupWorkItem` содержит только имя, id, ветку и папки. Поэтому фильтр нельзя встроить в `BackupRunFilter.Includes(BackupWorkItem)`: тот метод синхронный и работает без сети. Дату нужно получать из GitHub API.

## План изменений

```
PRD  ->  Core (дата + фильтр)  ->  Infrastructure (Octokit)  ->  Cli (опция)  ->  тесты и README
```

1. **`docs/PRD.md`** (по-русски). Нужна новая строка `--since <date>` в таблице FR-9.2 и правило в FR-9.x. Также нужны версия, дата и строка в истории изменений.
2. **`GitHubBackup.Core`:**
   - `GitHubRepository` получает поле `PushedAt` (`DateTimeOffset?`). Я не открывал этот тип, поэтому точную форму проверю при реализации.
   - Тот же `PushedAt` приходит из списков аккаунта (`/users/{login}/repos`, `/orgs/{org}/repos`), так что для аккаунтов лишних запросов не нужно.
   - `BackupRunFilter` получает необязательное `Since` (`DateTimeOffset?`) и фабрику для него. Сам `Includes` не меняется.
   - `BackupOrchestrator`: после discovery и перед обработкой отдельный шаг отбрасывает репозитории с `PushedAt < Since`. Для standalone-репозиториев он вызывает `GetRepositoryAsync`.
   - Пропущенные репозитории попадают в summary и лог с пометкой «пропущен: нет push после даты».
3. **`GitHubBackup.Infrastructure`:** маппинг `Repository.PushedAt` из Octokit в `GitHubRepository`.
4. **`GitHubBackup.Cli`:**
   - `CliCommandLine.cs`: `Option<DateOnly>("--since")` с валидатором и английским сообщением об ошибке (без значения в тексте).
   - `BackupCommandOptions` получает `Since`, а `CreateBackupOptions` передаёт его в фильтр.
   - `BackupCommandHandler` передаёт фильтр в `BackupRunRequest` как раньше.
5. **Тесты** в парных проектах: `CliCommandLineTests` (разбор, ошибка формата, будущая дата), `BackupRunFilterTests`, `BackupOrchestratorTests` (пропуск, граница «в этот день», нет даты) и `BackupCommandHandlerTests`.
6. **README.md** (по-английски): описание опции. `CLAUDE.md` и `docs/development.md` не меняются, потому что команды сборки те же.

## Предлагаемые решения

- **Формат даты:** `yyyy-MM-dd`. Граница включительная: начало этого дня в UTC, потому что GitHub отдаёт `pushed_at` в UTC.
- **Нет даты у репозитория** (пустой репозиторий, ошибка запроса): репозиторий **обрабатывается**. Лучше сделать лишний бэкап, чем пропустить нужный.
- **Сочетание опций:** `--since` работает вместе с `--account` и `--dry-run`. С `--repo` я бы запретил его в парсере, как `--account` и `--repo` друг с другом.
- **Связь с `ls-remote`:** `--since` только сужает список перед обычной быстрой проверкой. Проверка изменений остаётся как есть.

## Оговорки

- `pushed_at` меняется при push в любую ветку, но не при push в wiki. Репозиторий, у которого менялась только wiki, `--since` пропустит. Это нужно записать в PRD.
- Для каждого standalone-репозитория добавляется один запрос к API. Без токена действует анонимный лимит.
