## Главная трудность

Сейчас в модели нет даты push. `GitHubRepository` (`src/GitHubBackup.Core/GitHub/GitHubRepository.cs`) не хранит `pushed_at`. `BackupWorkItem` строится из `backup-config.json`, а не из ответа API. Октокит отдаёт `PushedAt`, поэтому нужно только пробросить это поле.

Обнаружение (`discoveryService`) не запускается при `--repo`, а список `items` приходит из конфигурации. Значит, дату для каждого элемента нужно получать отдельно.

## Что я бы изменил

```
CLI (разбор) → BackupRunFilter (условие) → BackupOrchestrator (отбор) → IGitHubApi (дата push)
```

1. **`GitHubBackup.Cli/CliCommandLine.cs`**: добавить `Option<DateOnly>("--since")` рядом с `--account` и `--repo`. Формат только `yyyy-MM-dd`, чтобы не зависеть от локали. Будущая дата даёт ошибку разбора. Опцию можно сочетать с `--account` и `--repo`; в PRD это нужно прописать явно.
2. **`BackupCommandOptions` и `BackupRunFilter` (Core)**: добавить `DateTimeOffset? PushedSince`. «С даты включительно» значит `PushedAt >= since` в UTC, с началом дня 00:00 UTC. Часовой пояс нужно зафиксировать в PRD.
3. **`GitHubRepository` и Octokit-обёртка (Infrastructure)**: добавить `DateTimeOffset? PushedAt`. Пустой репозиторий возвращает `null`.
4. **`BackupOrchestrator`**: после `SelectIncluded` добавить второй отбор по дате. Для каждого репозитория я бы брал `PushedAt` из результата обнаружения. Если обнаружения не было (`--repo`), я бы делал один `GET /repos/{owner}/{repo}`. Отсеянные репозитории получают статус `Skipped` с причиной «not pushed since <date>», как это сделано для других пропусков в FR-9.8. Каждый такой отсев пишется в лог.
5. **История запусков**: добавить `SinceFilter` в `RunHistoryEntry` и `RunEntity`, как уже сделано для `AccountFilter` и `RepositoryFilter`. Это требует миграции: `dotnet ef migrations add AddSinceFilter ...`. Руками миграцию править нельзя.
6. **Тесты**:
   - `Cli.Tests`: разбор даты, ошибки формата и будущей даты, совместимость с другими опциями.
   - `Core.Tests`: граница «ровно в эту дату» и `PushedAt = null`.
   - `Infrastructure.IntegrationTests`: история с новым полем.

## Что нужно решить до кода

- **Обнаружение при `--since`.** Выполнять ли его как обычно? Я предлагаю да: новые репозитории всё равно попадают в решения, а фильтр действует только на бэкап.
- **Wiki и `pushed_at`.** GitHub не обновляет `pushed_at` при изменении wiki, поэтому правка только в wiki не попадёт в запуск. Это нужно отметить в PRD как известное ограничение.
- **Лишние запросы API.** Для `--repo` потребуется один дополнительный запрос на репозиторий. Это важно в анонимном режиме с лимитом 60 запросов в час (FR-1.8).
- **Режим `--dry-run`.** Фильтр по дате должен работать и в нём, чтобы вы видели, что будет пропущено.
