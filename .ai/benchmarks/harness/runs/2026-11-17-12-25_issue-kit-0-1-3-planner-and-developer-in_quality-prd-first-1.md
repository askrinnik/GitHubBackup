**Кратко.** Опция `--since` небольшая только в консольной части. Основная работа лежит в Core и в API: сейчас у программы нет даты последнего push. Перед кодом нужно изменить PRD, потому что `.claude/rules/cli.md` требует этого для любой новой опции. Файлы я не менял.

## Что я выяснил

- `GitHubRepository` (`src/GitHubBackup.Core/GitHub/GitHubRepository.cs`) не содержит `PushedAt`.
- `BackupWorkItem` строится из `backup-config.json` и тоже не содержит даты.
- `BackupRunFilter.Includes(BackupWorkItem)` работает синхронно и без сети. Дату push можно узнать только у GitHub, поэтому в этот фильтр её класть нельзя.
- `BackupOrchestrator.SelectIncluded` вызывает фильтр для каждого элемента и пишет в лог `RepositoryFilteredOut`. Я не читал строку ~1155, где уже вызывается `GetRepositoryAsync`. Возможно, данные репозитория там уже запрашиваются, и тогда лишних запросов не будет. Это нужно проверить до плана.

## Вопросы, которые нужно решить до PRD

1. **Что такое «pushed to».** Поле `pushed_at` у GitHub не учитывает изменения wiki, потому что у wiki отдельный репозиторий. Репозиторий с изменённой wiki и старым push будет пропущен. Предлагаю описать это в PRD как известное ограничение. Другой вариант: не пропускать репозитории с `HasWiki`.
2. **Формат даты.** Предлагаю `yyyy-MM-dd`, начало суток по локальному времени (`TimeProvider.GetLocalNow()`). Согласны?
3. **Новые репозитории.** Репозиторий, найденный при discovery и ещё не клонированный, с push до `--since` будет пропущен, и первого бэкапа не будет. Предлагаю не фильтровать репозитории, у которых ещё нет клона.
4. **Ошибка API на одном репозитории.** По NFR-3 это сбой одного репозитория (`Failed`). Репозиторий не должен тихо исчезать из прогона.
5. **История запусков.** `RunHistoryEntryBuilder` сохраняет `AccountFilter` и `RepositoryFilter`. Если сохранять и `Since`, понадобится миграция EF (`dotnet ef migrations add`). Предлагаю пока не сохранять.
6. **Дополнительные запросы к API.** Нужно проверить, добавит ли шаг по `PushedAt` один запрос на репозиторий. Если да, то на больших аккаунтах стоит брать дату из списка репозиториев при discovery.
