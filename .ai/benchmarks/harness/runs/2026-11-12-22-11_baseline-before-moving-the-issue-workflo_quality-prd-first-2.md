**Коротко.** Это изменение нужно начинать с правки PRD, потому что `.claude/rules/cli.md` требует этого для любого нового параметра. Само изменение небольшое. Главная проблема в данных: сейчас приложение не знает дату push репозитория. Поэтому придётся добавить обращения к GitHub API. Файлы я не менял.

## Что я нашёл

- Фильтр запуска — `BackupRunFilter` (`Core/Runs`). Он знает только аккаунт и репозиторий. Оркестратор применяет его в `SelectIncluded` (`BackupOrchestrator.cs`, около строки 360).
- Список репозиториев для бэкапа берётся из `backup-config.json` (`BackupWorkItem.CreateAll`), а не из API. Обнаружение (discovery) только ищет новые, пропавшие и переименованные репозитории.
- `GitHubRepository` не содержит `pushed_at`. Список и одиночный запрос API (`GetRepositoryAsync`) возвращают репозиторий без этого поля.
- В PRD нет слова `--since`. Параметры `backup` описаны в FR-9.2.

## План по шагам

```
PRD → Core (модель + фильтр) → Infrastructure (Octokit) → Cli (параметр) → тесты → README
```

**1. PRD (сначала, нужно ваше одобрение).**
- В FR-9.2 добавить строку `--since <date>`.
- Поднять версию (сейчас 0.18) и добавить строку в историю изменений.
- Определить формат даты, границу и поведение при ошибках (вопросы ниже).

**2. Core.**
- В `GitHubRepository` добавить `DateTimeOffset? PushedAt`. GitHub возвращает `null` для пустых репозиториев.
- В `BackupRunFilter` добавить необязательное поле `Since` и фабрику вроде `WithSince(DateTimeOffset)`. Фильтр должен комбинироваться с `ForAccount` и `ForRepository`, поэтому нужны копирующие методы или `with`.
- Фильтр по дате не может жить в `Includes(BackupWorkItem)`, потому что `BackupWorkItem` не знает даты. Поэтому в оркестраторе после `SelectIncluded` добавить отдельный шаг. Он запрашивает `IGitHubApi.GetRepositoryAsync` для каждого оставшегося репозитория и пропускает те, у которых `PushedAt < Since`. Каждый пропуск пишется в лог через `[LoggerMessage]`, как `RepositoryFilteredOut`.
- Если запрос не удался или `PushedAt` равен `null`, репозиторий остаётся в запуске. Лучше сделать лишний бэкап, чем пропустить нужный. Ошибка запроса изолируется по репозиториям (NFR-3).

**3. Infrastructure.** В `OctokitGitHubApi` переносить `Repository.PushedAt` в новое поле. Это единственное место, где создаётся `GitHubRepository`.

**4. Cli.**

- Добавить валидатор через `ValidateValue` с константой сообщения. Значение в сообщение не попадает, как и у других параметров.
- Добавить поле `Since` в `BackupCommandOptions`. Метод `CreateBackupOptions` собирает его в фильтр.

## Предупреждения

- `pushed_at` меняется при push в любую ветку, но не при изменении wiki. Репозиторий, у которого менялась только wiki, `--since` пропустит. Это нужно записать в PRD.
- Для N репозиториев будет N запросов к API. Для личного бэкапа это приемлемо. Если репозиториев будут сотни, надо брать `pushed_at` из списков аккаунтов, которые обнаружение и так запрашивает. Это сложнее, потому что список сейчас обнаружению не передаётся.
- История запусков хранит `AccountFilter` и `RepositoryFilter` (`RunHistoryEntryBuilder`). Новое поле `SinceFilter` потребует миграции EF. Предлагаю не делать её в этой задаче.
